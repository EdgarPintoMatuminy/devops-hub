grep -Ril "o76" --include="*proxy*" .
grep -Ril "o76" --include="*.conf" .

🌐 WebLogic: Administración y Parcheo

🛠️ Procedimiento de Parcheo (SPBAT)

⚠️ Pre-requisito: Asegurar que el FS de /oracle tenga espacio suficiente (ej. ampliar de 10G a 20G). Ver con: df -h /oracle/
Bash
# 1. Backup: Realizar snapshot de la máquina virtual (Manual)

# 2. Parar procesos Java
/dominio/E01_PRU_WL122_OSB_INTER/custombin/stopE01_PRU_WL122_OSB_INTER_SVC111.sh
/dominio/E01_PRU_WL122_OSB_INTER/custombin/stopAdminServer.sh
sudo systemctl stop nodemanager
# (Repetir para otros nodos, ej. SVC121)

# 3. Rollback de parches conflictivos (si aplica, ej. 32720458)
/oracle/fmw/OPatch/opatch rollback -id 32720458 -silent

# 4. Aplicar parche con SPBAT
cd /coredumps
unzip p39221243_122140_Generic.zip
cd SOA_SPB_12.2.1.4.260417/tools/spbat/generic/SPBAT
./spbat.sh -phase precheck -oracle_home /oracle/fmw
./spbat.sh -phase apply -oracle_home /oracle/fmw

# 5. Arrancar procesos Java
sudo systemctl start nodemanager
/dominio/E01_PRU_WL122_OSB_INTER/custombin/startAdminServer.sh
/dominio/E01_PRU_WL122_OSB_INTER/custombin/startE01_PRU_WL122_OSB_INTER_SVC111.sh

📋 Plantillas de Resolución de INCs

Copia y adapta estas plantillas para tus respuestas en el sistema de tickets.

✅ URL carga correctamente (No se reproduce el error)
"Se ha revisado la infraestructura y se ha verificado que el Apache, las instancias de WebLogic y la aplicación se encuentran en buen estado. La siguiente URL carga correctamente y responde sin problemas: [INSERTAR URL]. Por lo tanto, no parece tratarse de un problema de la aplicación. Se recomienda revisar los permisos de acceso y las reglas del firewall como posible origen de la incidencia."
🔄 Reinicio de Servicios / Instancias (Alta Memoria/Swap)
"La alerta fue recuperada tras realizar un reinicio ordenado de las instancias/servicios que consumían mayor cantidad de memoria, liberando los recursos asociados y optimizando el uso de swap. Estas acciones estabilizaron el sistema, permitiendo su correcto funcionamiento."
📬 Metaposta (Atasco de paquetes)
"Se revisa la infraestructura de Metaposta y se detectan instancias en estado warning. De manera preventiva, se realiza un reinicio completo de todos los dominios, seguido del reinicio de la aplicación en el servidor correspondiente. Tras el reinicio, los paquetes atascados comienzan a publicarse correctamente. Se confirma: instancias OK, despliegues OK, colas JMS OK y datasources (DS) OK."
📉 Filesystem (Llenado de Logs)
"[GERTU_WEB] Se comprimen los logs antiguos que más memoria ocupaban. Estado actual del FS verificado y liberado."
